六、关键设计说明
------------------------------------------------------------

1. 消费端手动 ACK
   - application.yaml 中配置 acknowledge-mode: manual
   - prefetch: 1（每次只拉取 1 条，防内存溢出，公平分发）
   - 消费成功调用 channel.basicAck
   - 可重试异常调用 channel.basicNack(requeue=true)
   - 超过最大重试次数发送到死信队列

2. 生产者可靠性
   - publisher-confirm-type: correlated（生产者确认）
   - publisher-returns: true（路由失败退回）
   - 使用 CorrelationData 关联消息 ID

3. 死信队列 (DLQ)
   - 主队列配置 x-dead-letter-exchange 和 x-dead-letter-routing-key
   - 消息被 nack 且不入队时自动路由到 DLQ
   - DLQ 消费者记录失败订单到 Redis 待处理列表

4. 与原有 RocketMQ 功能对比
   - RocketMQ syncSend   -> RabbitTemplate.convertAndSend (同步)
   - RocketMQ asyncSend  -> RabbitTemplate.convertAndSend (异步，配合 CorrelationData)
   - RocketMQ @RocketMQMessageListener -> @RabbitListener + 手动ACK
   - RocketMQ 自动重试    -> RabbitMQ DLX 机制 + basicNack(requeue)
